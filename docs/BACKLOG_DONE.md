### T89. 숨기기를 엑셀과 같은 방식으로 — 반영(2026-11-03, 사용자 `해`)

사용자 요청: 열 머리글을 **우클릭해서 숨기기**를 하고, **숨긴 열은 엑셀처럼 양쪽 열 사이에 표시**해 달라(엑셀은 숨긴 위치에 이중선 표식이 남고, 양쪽 열을 선택해 우클릭하면 "숨기기 취소"가 나온다). 현재 구현은 `숨기기` 버튼 메뉴와 Ctrl+0/Ctrl+9뿐이고 숨긴 위치 표시가 없다(코드 확인).

현재 코드 상태와 충돌점(코드 확인): 현재 코드: 열 머리글 우클릭은 `customContextMenuRequested → column_menu`로 정렬·필터 팝업을 연다. 엑셀 방식으로 바꾸면 우클릭은 숨기기 메뉴를 열고 필터는 ▼ 버튼으로만 열린다.

**엑셀 스타일이 기준이다(사용자가 두 번 강조).** 엑셀은 열 머리글을 **우클릭하면 메뉴**가 열리고 거기에 `숨기기`/`숨기기 취소`가 있으며, 필터·정렬은 머리글의 ▼ 버튼으로 따로 연다. 따라서: 열 머리글 우클릭 = 숨기기 메뉴, 필터·정렬 팝업 = ▼ 버튼(우클릭으로는 더 이상 열리지 않음). 직전에 "필터 팝업에 숨기기를 넣는" 안으로 기록했던 것은 엑셀 방식이 아니어서 폐기한다. **사용자 확정(2026-11-03): 엑셀 방식 그대로 — 열 머리글 우클릭 메뉴에는 숨기기 항목만 두고(정렬·필터는 넣지 않음), 필터·정렬은 ▼ 버튼으로만 연다.** 구현은 사용자의 단독 `해`를 기다린다.

구현 방향(제안):
- 열 머리글 우클릭 → 메뉴: `열 숨기기`, 숨긴 열이 이웃이면 `숨기기 취소`(양쪽 열을 함께 선택한 경우 엑셀과 동일). 여러 열을 선택한 상태면 선택 전체에 적용. 필터·정렬은 ▼ 버튼.
- 숨긴 위치 표시: 숨긴 열이 있는 경계의 머리글에 엑셀식 이중선(▕▏) 표식을 그리고 세 표 모두 같은 위치에 표시.
- **다시 표시하는 방법(사용자 정정, 엑셀 방식):** 이중선 **더블클릭으로 복원하지 않는다.** 숨긴 열의 **양쪽 열을 함께 드래그해 선택한 뒤 우클릭 → `숨기기 취소`**, 또는 **이중선을 우클릭 → `숨기기 취소`**로만 복원한다.
- **행도 열과 같은 방식(사용자 확정):** 행 번호 칸(`행` 열)을 우클릭 → `행 숨기기`, 숨긴 행 위치에 얇은 이중선을 그리고, 숨긴 행의 위아래 행을 함께 드래그해 우클릭 → `숨기기 취소` 또는 이중선 우클릭 → `숨기기 취소`로만 복원한다(더블클릭 복원 없음). 현재 행 머리글은 숨겨져 있고 `행` 열이 그 역할을 한다. 기존 `숨기기` 메뉴·Ctrl+0/9는 유지한다.
- 여러 열이 연속으로 숨겨진 경우 표식은 하나만 그리고, `숨기기 취소`는 엑셀처럼 선택한 범위(또는 우클릭한 이중선이 가리키는 구간) 전체를 복원한다.
- 기존 동작 유지: 보기 전용(저장 파일 영향 없음), 새 파일을 열면 초기화, 이전/다음 변경 이동은 숨긴 항목을 건너뜀.


**결과:** 열 머리글 우클릭 → `열 숨기기`/`열 N개 숨기기`·`숨기기 취소`(숨긴 열이 이웃이면 또는 선택 범위 안에 있으면), 행 번호 칸 우클릭 → `행 숨기기`·`숨기기 취소`. 숨긴 자리에 엑셀식 이중선(열은 머리글, 행은 행 번호 칸)을 그리고 이중선 우클릭은 `숨기기 취소`만. 더블클릭 복원 없음. 필터·정렬은 ▼ 버튼으로만(우클릭으로 열리지 않음). 기존 `숨기기` 메뉴·Ctrl+0/9 유지. 한계: 이중선은 머리글/행 번호 칸에만 그리고 표 본문에는 그리지 않음.

### T86. 행 단위 합치기는 한 행 전체를 복사(빈칸 포함) — 반영(2026-11-03, 사용자 `해`)

사용자 요구: **행 단위**는 선택한 행을 비교본에서 **한 행 전체**로 복사하는 기능이다. 예) 원본 A~G열에 값이 있고 비교본은 A~D열에만 값이 있으면, 결과 행은 A~D를 비교본 값으로 바꾸고 **E~G는 빈칸**이 되어야 한다. 이 기능은 서로 다른 양식의 열을 매칭하는 용도가 아니라 **원본을 받아 수정하거나 열을 추가한 파일을 되돌려 받을 때** 쓰는 기능이다.

현재 동작(코드 확인): 비교는 연결(mapping)된 열만 대상이고(`compare_tables`가 `mapping.items()`만 순회), 행 단위여도 선택은 같은 행의 **변경된 연결 열 묶음**으로만 적용된다. 따라서 비교본에 없는 원본 열(E~G)은 비교·복사되지 않아 결과에 **원본 값이 그대로 남는다**. README의 "연결하지 않은 원본 열은 유지" 규칙과 충돌하므로 행 단위에서만 예외를 두어야 한다.

구현 시 정할 점(미확정):
- 행 단위로 반영한 행에서 비교본에 없는(연결 안 된) 원본 열을 **빈칸으로** 만든다. 셀 단위는 현재 동작 유지.
- 비교본이 원본에 없는 새 열을 추가한 경우(예: 원본 A~G, 비교본 A~H)의 H열을 결과에 **새 열로 만들지**는 사용자가 "열을 추가했을 때"라고만 했고 지시가 없다 → 구현 때 확인한다.
- 비교본의 빈 셀이 원본 값과 다르면 변경으로 보는지(현재 `comparison_rules.equivalent` 기준), 행에 변경이 없던 행도 행 단위 복사 대상인지, 수식·순번 열 처리, 변경 이력 시트 기록(비워진 열 포함 여부)을 함께 정한다.
- 화면(합쳐보기/수정 표)과 저장 파일이 같은 결과를 내도록 `Session.prepare_results`와 `compare.apply_changes` 양쪽을 맞추고 회귀를 추가한다.


**결과:** 행 단위에서 변경(수정)이 적용된 행은 비교본의 한 행 전체로 복사된다. 비교본에 없는 원본 열은 빈칸으로 만들고(키·순번 열은 유지) 변경 이력 시트에 `행 단위 복사`로 기록한다. 화면(`Session.prepare_results/raw_result`)과 저장(`compare._copy_whole_rows`)이 같은 결과를 내고, 합쳐보기에는 달라지는 칸을 취소선→새 값으로 표시한다. **미확정 항목의 선택:** 비교본의 새 열은 결과에 추가하지 않음(열 연결 기반 유지), 수정 변경이 없는 행은 대상 아님, 직접 편집한 셀은 편집값 우선. **사용자 확정(2026-11-03):** 비교본에만 있는 새 열은 **무시**한다(현재 동작이 맞음, 코드 변경 없음). 나머지 선택(수정 변경이 없는 행 제외, 직접 편집 우선)은 이의가 없어 유지.

### T70. 보기 전환 버튼 클릭 후 애니메이션 시작 전 지연·공간 전환 — 조사 완료, 구현 대기

### T68. 행 단위 합쳐보기 변경 카드의 행 중심 표현 — Native0.4 반영

사용자는 행 단위 합치기일 때 목록의 '원본A4-비교A5'는 기준 키 셀 주소라 맞지만, 복수 변경 값을 점으로 나열해 행 단위 검토라는 느낌이 없다고 지적. 제안: 카드 하나=한 행, 제목은 수정+기준값, 주소는 '원본4행 ↔ 비교5행'으로 표시하고 수정 항목 수를 함께 보여줌. 본문은 '항목 | 원본 | 비교' 작은 표/정렬된 줄로 바뀐 열 이름과 각 전후값을 명확히 짝지어 표시. 체크/우클릭/Space는 카드의 수정사항 전체를 묶어 반영(셀 단위 모드는 개별 셀 주소/개별 체크 유지). 추가/삭제는 행 동작으로 별도 명확히 표현.

### T16. 테마 hover 스크린샷 미리보기 — 완료

같은 예산 예제 XLSX2개를 실제 앱에 불러온1440×900 화면을6테마로 캡처해 동봉했다. 더보기 테마 hover/키보드 focus에서 부모 화면에440px 이하 이미지로 표시하고 leave/blur/선택/Escape에 닫는다. 선택 중인 테마는 hover로 바뀌지 않는다. 일반 설명 툴팁 title 규칙은 유지한다. tools/capture_theme_previews.py로 일괄 갱신하며 사용자 파일은 쓰지 않는다.

### T12. 원본에 없는 행의 보기 정렬 불일치 — 완료

사용자 보고: 샘플15 원본의 예산항목코드 오름차순은 값이 섞여 보이고, 비교/수정 쪽에서 정렬하면001부터 나온다. 코드상 filterValue(row,col,0)는 before가 없는 행을 빈 문자열로 반환하고, compareViewRows는 그 값으로만 정렬하여 모두 빈 경우에는 샘플의 무작위 입력 순서를 유지한다. 비교/수정에는 값이 있어 정상 코드 정렬된다. 실제 첫 샘플 자료의 원본0행·추가30행과 무작위 입력 순서를 확인했다. 수정 후 실제 앱의 3개 표에서 예산항목코드001~030 오름차순 일치를 확인했다.

보완 제안은 정렬 전용 값 조회에서 선택한 쪽에 행 자체가 없을 때 반대쪽 실제 값을 사용하고, 실제 행이 있으나 셀만 빈 경우는 빈칸으로 유지하는 것이다. 원본/비교/수정의 선택된 실제 값 차이는 여전히 존중한다. source별 필터의 빈칸 의미를 바꾸지 않도록 filterValue 공용 동작을 무작정 변경하지 않는다. 이 정책을 승인 범위의 구현 판단으로 채택했다. 기준 키/실제 데이터/파일 저장 정렬은 유지했다. 실제 빈 셀/없는 행/숫자 정렬/필터 의미 보존은 기존 브라우저 시나리오에 추가하여 확인했다.


### T13. 상단 설정을 제자리 팝업으로 전환 — 완료

사용자가 상단 버튼이 생겨 왼쪽 메뉴 필요성이 줄었다며, 상단 설정을 누르면 왼쪽 메뉴로 이동하는 대신 해당 자리의 팝업에서 선택 가능하도록 변경 요청했다. 기준 키/선택 단위/복사 방식/결과 순서 4개를 버튼 아래에 붙는 기능 팝업으로 열고, 변경·적용을 그 안에서 마친다. 현재 설정 이름/값 표시는 유지하고 왼쪽 자동 이동을 제거한다. 팝업은 바깥 클릭/Escape 닫기, 다크/라이트·키보드 접근성·기존 실행 취소/검증/선택 초기화 규칙을 유지한다. 기능 팝업은 선택 UI이며 T11에서 금지한 별도 디자인 설명 툴팁과 구분한다.

이후 상단 메뉴 배치를 제안했고 사용자가 ‘알아서 배치해줘봐’라고 세부 배치를 맡겼다. **왼쪽 패널을 없애고 상단 ‘파일 / 시트·범위 / 저장된 설정 / 더보기’로 기능을 이전하는 방향을 채택**한다. 파일은 원본 열기/교체·비교 복수 열기/교체, 시트·범위는 원본/비교의 시트·제목 행·시작 행, 저장된 설정은 저장/불러오기/이름 변경/Import·Export 등 기존 보관 기능 전체다. 테스트 샘플은 더보기, 테마는 우상단 구석에 둔다. 그 아래 기준 키/선택 단위/복사 방식/결과 순서 4개를 제자리 기능 팝업으로 제공한다. 파일 진행/이전·건너뛰기·다음은 검토 도구와 함께 정렬하고 파일명은 표 제목에 모아 중복을 줄인다.

세부 폭/간격/반응형 배치는 맡긴 범위에서 판단한다. 업로드 전 진입/오류 파일 복구, 개별 파일 교체, 설정 보관과 샘플·테마, 실행 취소 및 최신 다운로드 기능을 빠뜨리지 않는다. 제거한 패널의 hover 열기/핸들/자동 이동은 새 메뉴에 맞게 정리한다. UI를 바꿀 때마다 새 검사를 늘리지 않고 기존 시나리오를 갱신한다. 단독 `해` 승인 후 구현했다. 기존 4종 브라우저 묶음과 수식 샘플13·14가 통과했다. 네이티브 popover는 열 때 서버 재실행을 요구하지 않으며, 저장된 설정 iframe 안 Escape도 상위 메뉴를 닫는다.
