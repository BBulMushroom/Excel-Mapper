### 상태·통신 흐름

1. 업로드를 `formats.prepare()`로 내부 워크북 바이트로 준비한다. 이미 변환한 내부 XLSX를 원래 XLS/CSV 이름 때문에 다시 변환하지 않도록 prepared 플래그가 있다.
2. `detect_layout()`·`source_table()`로 표를 읽고 자동 열 연결과 기준 키를 선택한다. 사용자는 왼쪽에서 수정·적용할 수 있다.
3. `compare_tables()`가 차이를 만들고 `aligned_rows()`가 표 모델을 만든다. 서버 내부 삭제 유형은 `삭제 후보`, 프런트 표시 유형은 `삭제`다.
4. 압축 행 payload를 지속 컴포넌트 `workspace_persistent`에 전달한다. JS에서 체크와 보기 조작을 처리하여 매번 Python 전체 실행·표 교체를 피한다.
5. 저장/취합 요청에서 승인 ID와 revision/context를 검증하고 원본 바이트를 새로 열어 결과를 만든다. 저장 결과 바이트와 메타데이터를 반환한다.
6. `context`, `serverToken`, `historySession`, `revision`/`ack`, `rowPayload`, `rowsExpected`, `load_rows` 복구 경로를 유지해야 한다. 컴포넌트가 재생성될 때 행 데이터가 없으면 재요청한다.
7. 웹 작업 데이터는 세션 중심이다. 영속 작업 복구/서버 재시작 후 세션 복원은 구현되었다고 보장하지 않는다. `st.cache_data`는 별도의 메모리 캐시이며 로컬 설정 저장과 다르다.

## 4. 실제 적용된 동작·설정값

### 입력·비교·자동 설정

- 입력: **`.xlsx`, `.xlsm`, `.xls`, `.csv`**. CSV/XLS 결과는 XLSX이며 원래 형식으로 재저장하지 않는다. 원본 XLSM은 VBA 보존 로딩 및 XLSM 결과 경로가 있다. 비교파일 매크로 실행/가져오기를 지원한다는 뜻은 아니다.
- CSV: `utf-8-sig` 우선, 실패 시 `cp949`; 구분자는 쉼표/세미콜론/탭 감지. 셀 길이 32,767자 초과는 오류. 문자열을 임의 수식으로 실행하지 않도록 문자열 타입을 지정한다.
- 병합셀이 있는 **비교 대상 데이터 시트**는 거부한다. 빈/중복 열 이름, 중복/빈 기준 키, 수식 기준 키도 차단한다.
- `normalized()`: None/NaN→빈 문자열, 정수형 숫자는 정수 문자열, 나머지는 문자열 양끝 공백 제거. `00123` 문자열과 숫자 123은 구분된다. 값 비교는 이 정규화 기준이며 표시 서식·조건부서식 차이를 비교하는 엔진은 아니다.
- **순번은 파일 내 순서**이고 고유 키가 아니다. 자동 열 연결/키/수정 비교에서 제외하며 결과에서 존재하는 순번 열을 다시 연속 번호로 만든다.
- 열 연결 추천은 실제로 **이름 20% + 자료형 20% + 공통값 60%**, 전체 행 기반이다. 점수는 확률이 아니다. 정확한 동일 이름을 먼저 연결한 후 남은 열을 점수 **50 이상**에서 일대일로 연결한다. 모든 경우를 보장하는 AI 추론이 아니다.
- 자동 기준 키는 위 가중치 점수와 별도 로직이다. 저장 프로필→현재 세션의 같은 양식 기억→`suggested_keys()` 순서. 코드/번호/code/id 등 안정 식별자 우선, IP 그다음, 단일 키 및 복합 키의 빈값/수식/중복 검증을 거친다. 안정 열 조합은 최대 3개, 기타 보완 조합은 2개까지 탐색한다. 사용자가 직접 여러 키를 지정할 수 있다.
- 시트/제목/시작 자동 감지는 각 시트 선두 **80행**을 조사하며 `변경 이력` 시트는 제외한다. 일반 기본값은 제목 1행/시작 2행. 자동 감지가 항상 정확하다는 뜻은 아니므로 왼쪽 ‘비교할 데이터’에서 원본/비교를 각각 수정할 수 있다.
- `app.py`의 캐시: 시트 목록 `st.cache_data(max_entries=24, show_spinner=False)`. v0.27.0부터 표는 전역 Streamlit 캐시 대신 사용자 세션의 `AnalysisCache`(표 4개/레이아웃 8개)에서 읽고 생성 메타데이터를 재사용한다. 캐시는 VERSION 변경 시 재생성된다. 같은 context/검토 단위/복사/정렬/승인 선택의 ExportResult 1개도 재사용한다. 출처 바이트·시트·범위를 다른 파일에 잘못 재사용하지 않도록 검증했다.

### 승인·검토·표 UI

- 기본 선택은 **추가·수정 ON / 삭제 OFF**. 삭제 없는 추가 자료를 받아도 원본 항목이 자동 삭제되지 않는다. 삭제는 명시적으로 승인할 수 있다.
- 기본 검토 단위는 **셀 단위**, 사용자가 **행 단위**로 전환 가능. 행 단위는 같은 키의 수정 차이를 묶어 선택하며, 원본 전용 열까지 무조건 덮어쓰는 동작은 아니다. 빈칸 변경도 실제 차이로 취급한다.
- 기본 복사는 **일반 복사**, 기본 결과 순서는 **원본 순서 유지**. 직접 정렬은 별도 설정이며 표에서의 보기 정렬/필터와 파일 저장 정렬은 다르다. 보기 기본 정렬은 선택 기준 키의 첫 열이다.
- 표 이름은 **원본 / 비교 / 수정**. 나눠보기 3개 표와 합쳐보기(왼쪽 약 2/3 표 + 오른쪽 약 1/3 변경목록)를 전환한다. 합쳐보기 수정값은 원래 값 취소선과 새 값을 위/아래로 표시한다.
- 순서는 항상 **추가 / 수정 / 삭제**. 색은 추가 초록 `#dcfce7`, 수정 주황 `#ffedd5`, 삭제 빨강 `#fee2e2`. 선택 버튼은 원 안의 플러스/연필/마이너스와 건수이며, 전부 해제된 경우에만 회색 점선 상태다. 일부 선택은 선택 건수로 구분한다.
- 셀 주소와 실제 파일 행/열 좌표를 표시한다. 원본↔비교 관계는 **양방향 `↔`**를 사용하며 없는 쪽은 `—`. 저장 후 실제 재배치 주소와 원본/비교 참조 주소를 혼동하지 않는다.
- 수정 셀뿐 아니라 행 클릭도 변경목록을 연결한다. 표와 목록 양방향 이동/강조, 이전·다음 변경 탐색, 선택 셀 강조, 텍스트 드래그/Ctrl+C를 제공한다.
- 배율은 **60·75·85·100·115·125%**, 기본 100%. 표 위 Ctrl+휠로 변경하며 표 밖 브라우저 기본 동작은 유지한다.
- 행 높이·열 너비는 드래그 조절 및 경계 더블클릭 자동 맞춤, 세 표 동기화, 실행 취소/다시 실행을 지원한다. 초기 로딩 때 모든 행/제목을 보고 열 너비를 맞춘다. 보기 너비·높이를 다운로드 파일 서식에 그대로 쓰는 기능은 아니다.
- v0.26.0부터 **행·기준값 고정 열도 동일 조절**을 지원한다. JS `columnWidths` Map은 행 열 키 **null**, 기준값 열 키 **false**, 일반 열 키 문자열을 사용한다. 이는 실제 열 이름과 충돌을 피하기 위한 구현이다. 드래그 최소 논리 너비 **48px**. fallback 64/76px는 초기 자동 맞춤 전 값이며 최종 고정 너비가 아니다.
- 표마다 **18px** 세로 레일에 전체 너비 색상 인디케이터와 투명 트랙/반투명 핸들이 있다. 세 표 스크롤은 동기화, 변경목록은 독립 스크롤이다. 가로 스크롤은 표별로 표시한다.
- 열 필터: 제목 옆 팝업, 같은 열 다시 클릭/외부 클릭/Escape 닫기. 값 검색/전체 체크/빈값, 텍스트·숫자·날짜 조건, AND/OR, 범위·상하위 N·평균·상대 날짜, 정렬/해제, 열 필터 지우기. 값·조건은 확인 전 적용하지 않고 취소 시 버린다. 정렬/필터 지우기는 즉시 적용한다. 1만 값 목록도 가상화한다.
- Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z는 방금 전 **정확한 상태**를 복구한다. 예: 80건 중 40건 선택→전체 해제→되돌리기는 이전 40건을 복구. 설정 변경 이력은 서버 토큰과 프런트 스냅샷을 함께 사용한다. 이미 다운로드한 외부 파일 자체를 되돌리는 기능은 아니다.
- 왼쪽 메뉴는 hover로 열고 **외부 클릭 시 닫는다**. 마우스가 나갔다고 닫지 않는다. 상단 중복 화살표는 숨기고 중앙의 작은 회색 핸들을 사용한다. 다크모드는 메뉴 맨 아래에 있다.
- 상단의 기준 키·검토 단위·복사 방식·결과 정렬 상태 버튼은 왼쪽 해당 설정으로 이동한다. 툴팁은 해당 기능의 의미를 설명한다. v0.26.0에서 펼침 헤더는 삼각형/굵은 글씨, 동작은 버튼, 선택은 입력창 형태로 구분했다.

### 수식·서식·결과 파일

- 결과는 **원본 워크북을 열어 선택 변경을 적용한 별도 파일**이다. 원본 전용 열과 승인하지 않은 셀은 보존한다. 미리보기는 원본의 조건부서식/모든 Excel 표시 서식을 재현하는 렌더러가 아니다.
- 일반 복사는 출처 셀의 실제 수식 타입을 확인하고 `openpyxl.formula.translate.Translator`로 상대/절대참조를 목적 좌표에 맞춘다. 출처가 없는 `=` 시작 문자열은 리터럴로 둔다.
- 일반 복사는 글꼴·채우기·테두리·정렬·표시 형식·보호·메모·하이퍼링크를 복사한다. 서로 다른 워크북의 스타일 ID를 직접 공유하지 않고 속성별 `copy()`를 사용한다.
- 명시적 다른 시트 참조는 비교파일 시트를 **별도 `(비교)` 스냅샷**으로 가져온다. 이름 충돌은 번호로 구분하며 참조 의존성도 처리한다. 원본의 같은 이름 시트를 덮어쓰지 않고 외부 링크를 새로 만들지 않는다.
- 값만 복사는 비교파일의 **마지막 저장 계산 캐시**를 쓴다. 0과 실제 빈 문자열 결과도 구분한다. 캐시가 없으면 미리보기 `계산값 없음`, 저장은 주소를 포함한 오류로 차단한다. 임의로 수식을 계산하거나 빈 값으로 저장하지 않는다.
- 복사 라디오 전환은 수정본·합쳐보기·변경목록 미리보기에 반영한다. 원본/비교 표는 파일 내용을 보여준다. 미리보기 문자열과 최종 목적 좌표로 조정된 실제 수식은 구분해서 검증한다.
- 수식 계산 엔진은 없다. 결과에 `calcMode='auto'`, `fullCalcOnLoad=True`, `forceFullCalc=True`를 설정해 Excel 재계산을 요청한다. openpyxl 저장 후 캐시가 계속 남는다고 보장하지 않는다.
- Excel 전체 붙여넣기와 동일하지 않다. 조건부서식·유효성검사·개체의 복제/범위 확장, 모든 복잡한 참조 재작성은 보장하지 않는다. 기존 원본 구조도 openpyxl의 보존 범위에 영향을 받는다.
- 안전 제한: 워크북에 수식이 있으면 행 삭제 차단, 대상 시트에 수식이 있으면 결과 정렬 차단. Excel Table이 있는 대상 시트는 셀 수정만 지원하고 행 추가·삭제·정렬은 차단한다.
- 일반 복사에서 외부 파일/3차원/이름 정의/표 구조 참조/배열 수식은 지원하지 않으며 오류 안내한다. 비교 열과 원본 열의 의미가 바뀌는 복잡한 수식 의미 보정까지 해결한다고 보장하지 않는다.
- 이력은 **한 개의 `변경 이력` 시트에 누적**한다. 열은 `변경 유형, 키값, 대상 열, 변경 전, 변경 후, 승인 및 적용, 처리 일시`. 시간대는 **Asia/Seoul**, 승인하지 않은 후보도 기록한다. 같은 이름의 일반 시트와 형식이 충돌하면 오류다. 구버전 날짜 이름 로그는 형식이 일치하는 경우만 통합한다.

### 다중 파일 취합·설정 보관

- 원본과 비교파일은 각각 독립 교체 가능. 비교파일은 여러 개 업로드하여 업로드 순서대로 반영/건너뛰기/이전 이동한다. 반영 후 다음의 누적본이 다음 단계 원본이다. 완료 후 최종 결과를 다운로드한다.
- `queue_versions`는 단계별 바이트·이름·레이아웃, `queue_reviews`는 기준 원본 해시와 승인 ID를 보관한다. 이전 단계로 돌아가 다시 적용해도 같은 행을 중복 추가하지 않는다. 앞 단계 결과가 달라지면 뒤 단계 승인 재사용을 피한다.
- 비교 교체는 현재 누적 원본을 유지하고, 취합 완료 후 교체는 최종 누적본을 사용한다. 검토 오류 파일도 건너뛰기/이전 이동 가능하지만 해독 자체가 안 되는 업로드는 처음 준비할 때 오류가 난다.
- 웹 설정 보관 위치: 브라우저 localStorage **`excel-review.settings.v1`**. 테마 키: **`excel-mapper-theme`**. 브라우저/출처별 저장이며 데이터를 지우면 사라진다. 서버 사용자 공용 JSON에 저장하지 않는다.
- 프로필 schema `version:1`, 보관함 `{version:1, items:[{id,profile}], activeId}`. 최대 **500개**, 이름 **100자**. 웹 Import는 **2 MiB** 제한이다. 엑셀 업로드 크기 설정과 관계없는 설정 JSON 제한이다.
- 보관 대상: 키·열 연결·시트/제목/시작·검토 단위·복사 방식·결과 정렬. 엑셀 데이터와 개별 승인 체크는 프로필에 넣지 않는다. Import 이름 충돌은 새 이름, 적용 시 필요한 열/키가 없으면 거부한다.
- 향후 네이티브 기본 경로: Windows `%APPDATA%/ExcelReview/settings.json`; Linux는 `$XDG_DATA_HOME/ExcelReview/settings.json`, 없으면 `~/.local/share/ExcelReview/settings.json`. `FileSettingsStore`는 검증 후 임시 파일·fsync·원자적 교체를 수행한다. 현재 웹에서 이 경로를 사용한다는 뜻은 아니다.
- `.streamlit/config.toml`: `server.headless=true`, `server.maxUploadSize=2147483647` **MB**, `browser.gatherUsageStats=false`, `theme.primaryColor='#2563eb'`. 앱의 과거 20MB 제한 대신 Streamlit 지원 정수 최대값을 사용한다. 호스팅·메모리·브라우저 제한까지 없어졌다는 뜻은 아니다.

- 신규자료 전용/일부 갱신 모드를 여러 개 강요하는 대신 전체 차이를 제시하고 종류별·개별 승인을 제공한다. 비교에 없다는 이유만으로 관리대장을 잃지 않도록 삭제 기본은 해제로 결정했다.

UUID는 인증정보가 아닌 작업 식별자다.

**마지막 파일 동작:** `queue_complete`는 여전히 결과가 한 번 반영되었음을 나타내지만 편집 잠금을 뜻하지 않는다. 체크와 종류별 버튼을 계속 사용할 수 있다. 프런트는 `queue.applied`/`outputCurrent`를 기준으로 ‘변경사항 있음’을 표시한다. 다시 반영하거나 최종 다운로드하면 마지막 단계 반영 전 바이트에서 현재 승인으로 생성해 중복을 막는다. 설정/승인이 같을 때만 마지막 ExportResult를 재사용한다. 복사/정렬/검토 설정이 바뀌면 재생성한다. 처리가 실제 진행 중일 때만 임시 잠금하며 응답에서 해제한다. 기존 ‘이전 파일’의 완료 해제 시 마지막 단계 재활성화 동작은 유지했다. 최종 건너뛰기는 반영 선택을 비우고 기준 누적본 다운로드를 유지한다.

**성능 구현:** `analysis_cache.py`는 SHA-256 바이트 식별과 시트/제목/시작 행 조합으로 캐시한다. 생성 결과의 Table과 레이아웃을 seed하여 다음 단계 누적 원본 파싱을 피한다. 설정 복원 후에도 출처 일치가 필요하며 다른 범위는 다시 읽는다. 백그라운드 prefetch는 도입하지 않았고 새 의존성도 없다. `ExcelCopy.styles`는 출처 style ID를 목적 워크북의 StyleArray로 한 번 등록한 후 목적 스타일만 복사한다. 셀별 메모·링크는 캐시하지 않고 매번 복사한다. 원본에서 다른 워크북으로 출처 style ID를 직접 복사하는 잘못된 최적화가 아니다. `compare._apply_changes()`는 추가 행마다 max_row/max_column을 다시 계산하지 않고, 수식 보호 검사에서 서식만 있는 거대한 빈 사각형을 순회하지 않는다. 같은 취합 양식의 열 너비는 새 비교값 기준으로 확장하되 사용자 드래그 너비를 줄이지 않는다. 수동 더블클릭은 여전히 모든 원본/비교/미리보기 행을 측정한다.
