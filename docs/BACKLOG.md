## 개선 후보(제안, 사용자 미승인)

사용자가 "범용으로 쓸 수 있도록 더 필요한 기능을 찾아 달라"고 요청해 코드·문서에서 찾은 후보이다(2026-11-03). **구현하지 않았고 승인도 받지 않았다.** 근거는 코드/문서 확인 사실이며, 효과·우선순위는 추정이다. 사용자가 번호를 골라 `해`를 보내면 요청 목록으로 옮겨 구현한다.

**A. 신뢰성·사용성(먼저 권장)**
- C1. **작업 중 진행 표시와 취소**: `run()`은 처리 중 메뉴·표를 모두 비활성화하지만 진행 문구는 숨겨진 상태 표시줄(`statusBar().hide()`)에만 넣어 사용자에게 **보이지 않는다**. 1만 행 로딩도 수 초간 멈춘 것처럼 보임. 진행 막대/스피너와 취소 버튼, 단계별 문구(파일 읽기·비교·저장) 필요.
- C2. **파일 끌어다 놓기(드래그 앤 드롭)와 최근 파일**: 코드에 drop 처리·최근 파일이 없다(확인). 파일 열기는 메뉴 대화상자뿐. 창에 원본/비교 파일을 놓으면 열고, 최근 사용 목록과 Ctrl+O를 지원.
- C3. **지원하지 않는 파일 구조를 사전에 안내**: 병합셀·수식 시트 정렬·수식 파일 행 삭제·표(Table)·배열/이름 정의 수식은 오류로 중단(`compare.py`, `excel_copy.py`). 불러올 때 어떤 기능이 제한되는지 한 번에 요약해 보여 주고, 조건부 서식·데이터 유효성·차트·그림 등 **보존이 보장되지 않는 개체가 있으면 저장 전 경고**(현재는 문서에만 "보장하지 않음").
- C4. **병합셀 지원**: 실무 파일에서 가장 흔한 거절 사유. 병합 영역을 값 하나로 읽고 쓰는 방식 또는 병합 해제 후 처리 옵션.
- C5. **검토 상태 저장·불러오기**: 반영 선택·직접 편집·열 연결을 파일(프로젝트)로 저장해 다음 날 이어서 작업. 비정상 종료 복구(자동 저장). 현재 실행 취소는 40단계 메모리 한정.
- C6. **변경 내역 내보내기**: 변경 이력은 결과 엑셀의 `변경 이력` 시트에만 있다. 비교 결과 요약(열별 변경 수, 추가/수정/삭제 건수)과 변경 목록을 별도 파일(xlsx/csv, 인쇄용)로 내보내기.

**B. 범용성**
- C7. **여러 시트 한 번에 비교**: 지금은 선택한 시트 하나만 비교. 시트 이름 기준 자동 짝짓기와 시트별 결과.
- C8. **열 연결 개선**: 제목 공백·대소문자 차이 자동 정규화, 위치 기준 연결 옵션, 유사 이름 추천(문서상 후속 범위: "키 불일치 유사 장비 제안, 자동 템플릿 탐지"). 열 순서 변경·새 열 처리 방식은 사용자가 이미 정함(원본에 없는 열 무시).
- C9. **저장 형식 선택**: 입력은 XLSX·XLSM·XLS·CSV를 받지만 출력은 XLSX/XLSM뿐(`formats.py`에서 XLS/CSV는 XLSX로 변환). 원본이 CSV/XLS일 때 같은 형식으로 저장하는 옵션.
- C10. **대용량 대응**: 1만 행 기준 파일 하나 읽기 약 1.3초(openpyxl 전체 로드). 10만 행은 약 13초+메모리 부담 추정. 읽기 전용 스트리밍, 진행 표시(C1), 메모리 상한 안내.
- C11. **명령줄/일괄 실행**: 엔진은 UI와 분리되어 있어 `ExcelMapper.exe --compare 원본 비교 --out 결과`처럼 자동화할 수 있다(미구현). 폴더 단위 반복 취합.

**C. 배포·운영**

- C14. **다국어(영어 UI)**: 현재 한국어 문자열이 코드에 고정. 범용 배포 시 언어 선택.

### T93. 삭제 행을 반영(체크)하면 취소선 셀의 좌우 정렬이 틀어짐 — 반영(0.12.0, 사용자 `해`)

사용자 보고(0.11.0): 3번 세트 첫 삭제 행(`ITEM0002 / 서울창고`)에서 취소선이 그어질 때 좌우 정렬이 틀어진다.
- **재현·원인(조사만, 코드 미수정):** 합쳐보기에서 삭제 항목을 선택(체크)하면 `build_merged_html`(`desktop/models.py` 163줄)이 취소선 HTML을 만들고, 이 셀은 `QTextDocument`로 그려져 항상 왼쪽 정렬이다. 선택 해제 상태는 일반 텍스트 경로라 숫자 열(수량·단가)이 0.11.0의 우측 정렬을 따른다. 그래서 체크하는 순간 숫자 셀만 오른쪽에서 왼쪽으로 튄다. 수정 셀(`<s>이전값</s><br>새값`)도 같은 경로다.
- **수정안:** HTML 경로도 숫자 열이면 문서 정렬을 오른쪽으로 하고 폭 계산(`setTextWidth`)과 좌우 여백(왼쪽 6/24, 오른쪽 22)을 일반 경로와 맞춘다. 테스트: 숫자 열 셀의 체크 전후 글자 오른쪽 끝 위치가 같음.

### T94. 테스트 세트를 불러올 때 로딩바가 안 보임 — 반영(0.12.0, 사용자 `해`)

사용자 보고(0.11.0): 테스트 샘플을 불러올 때 로딩바가 나오지 않는다.
- **재현·원인(조사만):** 샘플 3번은 백그라운드 작업(샘플 읽기 0.12초 + 세션 0.07초)이 오버레이 지연 시간(250ms)보다 먼저 끝나 오버레이가 한 번도 뜨지 않는다. 이후 메인 스레드의 화면 갱신(`refresh`+그리기, 이 환경 0.65초)이 로딩바 없이 화면을 멈춘다. Windows에서는 더 길 수 있다.
- **추가 보고:** 맨 처음 한 번은 로딩바가 나오고 같은 세션에서 다시 불러오면 안 나온다 → 첫 로드는 샘플 생성·모듈 로딩으로 250ms를 넘기고, 이후에는 캐시되어 0.2초 안에 끝나 오버레이 지연에 걸리지 않는 것과 일치한다(원인 확인 결과와 같다).
- **수정안:** 오버레이를 백그라운드 작업이 끝난 뒤 화면 갱신이 끝날 때까지 유지하고(`stop`을 갱신 후로 이동, 갱신 전 `processEvents`로 한 번 그림), 표시 지연을 250→100ms로 줄인다(사용자 확정: 지연 0.1초, 지연 0·최소 표시시간 안은 채택 안 함). 테스트: 샘플 로드 중 갱신 단계에서 오버레이가 보임.
